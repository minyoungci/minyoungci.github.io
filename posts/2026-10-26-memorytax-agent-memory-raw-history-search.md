AI 에이전트에 기억 장치를 따로 달 필요가 정말 있는지 따져 본 논문이 나왔다. 제목은 MemoryTax: The Bitter Lesson of Agent Memory(arXiv:2610.29823)다. 상하이교통대(Shanghai Jiao Tong University)의 Zedong Peng이 혼자 쓴 11쪽짜리 논문으로, 한국 시간 10월 21일 밤 arXiv에 올라왔다. 연구자는 긴 대화 하나를 두고 기억 방식 4가지와 코딩 에이전트 3종, 모두 7가지 방법에 언어 모델 3종을 조합했다. 그리고 질문 152개를 얼마나 맞히는지, 돈은 얼마나 드는지를 함께 쟀다.

결과의 줄기는 이렇다. 대화에서 사실을 미리 뽑아 저장하는 Mem0는 가장 약한 GPT-4o-mini와 짝을 지었을 때만 대화 전체를 통째로 넣는 방식을 앞섰다. 더 강한 모델에서는 그런 이점이 사라졌다. 가장 강한 Claude Opus 5.5가 Pi라는 코딩 에이전트로 원본 대화 파일을 직접 검색하자, 정답률 99%를 6.95달러에 기록했다. 대화 전체를 넣은 방식은 95%에 17.84달러였다.

하지만 "기억 장치는 이제 필요 없다"는 한 줄 요약은 지나친 해석이다. 실험한 대화는 하나뿐이고, 조합마다 한 번씩만 돌렸다. 채점은 너그러운 기준을 적용한 GPT-4o-mini가 맡았다. 에이전트가 앞선 차이의 대부분은 에이전트만 읽을 수 있었던 사진 설명에서 나왔다. 이 지면은 논문 전문을 직접 읽고, 실험이 무엇을 쟀는지, 숫자가 무엇을 말하고 무엇을 말하지 않는지 차례로 확인한다.

## 1. 먼저 알아 둘 것, 에이전트의 기억은 두 갈래다

AI 에이전트가 오래 일하려면 지난 대화를 기억해야 한다. 고객 상담 에이전트라면 몇 달 전 고객이 무엇을 샀고 무엇을 약속받았는지 알아야 한다. 이때 고를 수 있는 길은 크게 두 가지다.

첫째는 미리 정리해 두는 길이다. Mem0와 Zep 같은 '에이전트 메모리' 시스템이 여기에 속한다. 대화가 쌓이는 동안 언어 모델이 중요한 사실을 뽑아 저장하거나(Mem0), 사람과 사건을 잇는 지식 그래프를 만든다(Zep). 나중에 질문이 들어오면 저장해 둔 조각 가운데 관련 있는 몇 개만 꺼내 모델에게 보여 준다.

둘째는 원본을 그대로 두는 길이다. 대화 기록 전체를 파일로 보관하고, 질문이 들어오면 모델이 스스로 도구를 써서 필요한 부분을 찾아 읽는다. Pi, Codex, Claude Code 같은 코딩 에이전트가 이렇게 일한다. 코드 저장소를 뒤지듯 대화 기록을 뒤지는 것이다.

두 길의 차이는 '무엇을 남길지 언제 정하느냐'에 있다. 첫째 길은 질문이 오기 전에 정한다. 둘째 길은 질문을 보고 나서 정한다. 논문은 이 대비를 강화학습 연구자 Richard Sutton의 에세이 「쓰라린 교훈(The Bitter Lesson)」에 빗댄다. 사람이 설계해 넣은 지식은 처음에는 도움이 되지만 얼마 뒤 정체되고, 계산량을 늘릴수록 좋아지는 일반적인 방법이 결국 이긴다는 주장이다. 논문 제목의 '쓰라린 교훈'이 여기서 왔다.

연구자가 던진 질문은 하나다. 모델이 스스로 찾아볼 만큼 똑똑해져도, 미리 설계한 기억 장치가 여전히 도움이 되는가.

## 2. 실험 설계, 대화 하나에 방법 7가지와 모델 3종

무대는 LoCoMo라는 장기 대화 벤치마크다. 연구자는 LoCoMo의 대화 10개 가운데 conv-26 하나를 골랐다. 19개 세션에 걸친 419턴짜리 대화이고, 질문은 152개다. 질문은 한 곳만 보면 되는 단일 정보 질문 70개, 여러 곳을 이어야 하는 다중 정보 질문 32개, 시간 순서를 묻는 질문 37개, 대화 밖 일반 지식이 필요한 질문 13개로 나뉜다. LoCoMo의 함정 질문(adversarial)은 Mem0 연구진의 평가처럼 뺐다.

방법은 기억 방식 4가지와 코딩 에이전트 3종, 모두 7가지다. 표 1은 논문 표 1을 옮긴 것이다.

BM25는 검색 엔진에서 오래 써 온, 단어 일치에 기반한 검색 방식이다. 언어 모델을 쓰지 않고 질문과 단어가 겹치는 대화 조각을 골라 준다.

Mem0와 Zep은 각자의 기본 설정을 그대로 썼다. 부록 B에 따르면 Mem0는 대화를 한 턴씩 시간 순서대로 기록하고, 질문이 오면 사실 200개를 재정렬 없이 꺼낸다. 기록하는 각 턴의 글 앞에는 날짜를 붙였다. Zep은 세션 하나를 한 단위로 그래프에 넣고, 질문이 오면 연결 20개를 찾아 준다.

모델은 약한 것부터 GPT-4o-mini, GPT-6 Luna, Claude Opus 5.5 순으로 세 가지를 썼다. 뒤의 두 모델은 추론 강도를 '높음(high)'으로 맞췄다. 7가지 방법에 모델 3종을 곱해 모두 21개 조합을 돌렸다. 논문은 이를 셀(cell)이라고 부르고, 이 지면은 '조합'이라고 쓴다.

에이전트 쪽 설정도 꼼꼼하다. 질문마다 새 컨테이너에서 새 세션을 열고, 그 안에는 대화 파일 하나만 둔다. 에이전트가 일하는 동안 컨테이너는 모델 API 외에는 어디에도 연결할 수 없다. Codex와 Claude Code는 웹 검색을 껐다. 질문 하나에 최대 20분, Pi와 Claude Code는 최대 100턴까지 허용했다.

비용은 임베딩을 포함한 모든 모델 호출의 정가(list price)로 계산했다. 기억 장치를 만드는 비용과 질문에 답하는 비용을 모두 더했고, 채점에 든 비용만 뺐다. 채점은 GPT-4o-mini가 Mem0 연구진의 2025년 채점 기준으로 했다. 이 기준은 채점 모델에게, 생성된 답이 정답과 같은 주제를 다루기만 하면 너그럽게 정답으로 처리하라고 지시한다. 빈 답은 오답으로 쳤다.

주의할 설정이 하나 있다. LoCoMo의 일부 턴에는 사진이 붙어 있고, 공식 파일에는 그 사진의 설명 문장이 함께 들어 있다. 에이전트는 공식 파일을 그대로 받아 사진 설명까지 읽을 수 있었다. 기억 방식들은 턴의 본문만 받았다. 419턴 가운데 116턴에 사진이 있고, 질문 152개 가운데 64개는 답의 근거가 그런 턴에 있다. 이 차이는 6장에서 다시 다룬다.

## 3. 첫째 발견, 미리 정리한 기억은 약한 모델에만 통했다

GPT-4o-mini와 짝을 지었을 때는 Mem0가 가장 잘했다. 정답률 78%로, 대화 전체와 BM25의 74%를 앞섰다. Zep은 43%에 그쳤다. 에이전트는 Pi 63%, Codex 28%, Claude Code 29%였다. 논문에 따르면 Codex는 네 질문 중 세 질문에서만 대화 파일을 열었고, Claude Code는 거의 열지 않았다. 나머지는 질문만 보고 답했다. 약한 모델은 도구를 쥐여 줘도 잘 쓰지 못했다.

모델이 강해지자 이 이점은 사라졌다. GPT-6 Luna에서는 대화 전체가 92%로 가장 높았고, BM25 82%, Mem0 80%, Zep 51%였다. Claude Opus 5.5에서는 Mem0와 대화 전체가 똑같이 95%, Zep이 87%였다. 같은 모델의 에이전트는 Pi 99%, Codex 98%, Claude Code 97%로 가장 높았다.

표 2는 논문 부록 표 2에서 질문 152개 전체의 정답률만 옮긴 것이다. 각 조합은 한 번씩만 돌렸다.

Zep 그래프의 크기도 모델마다 달랐다. GPT-6 Luna가 19개 세션으로 만든 Zep 그래프에는 사실이 128개 담겼다. Claude Opus 5.5가 만든 그래프에는 195개가 담겼다. 논문은 이 차이를 점수 차이의 원인으로 단정하지는 않았다.

## 4. 기억을 만드는 값, 질문 152개로는 본전을 못 뽑는다

논문이 제목에 '세금(tax)'을 붙인 이유는 비용이다. Mem0는 기억을 만드는 비용만으로 대화 전체 방식의 한 바퀴 비용을 넘었다. 한 바퀴(rollout)는 기억 장치를 만든 뒤 질문 152개에 모두 답하기까지의 전 과정을 뜻한다.

GPT-4o-mini에서는 Mem0를 만드는 데만 0.56달러가 들었다. 대화 전체 방식은 질문 152개에 다 답하고도 0.43달러였다. GPT-6 Luna에서는 0.45달러 대 0.29달러, Claude Opus 5.5에서는 25.88달러 대 17.84달러였다.

만든 뒤에는 Mem0가 더 싸다. 부록 표 2를 보면 GPT-4o-mini 기준 질문당 비용이 Mem0는 0.0013달러, 대화 전체는 0.0028달러다. 그래서 같은 대화에 질문을 계속 던지면 언젠가는 본전을 뽑는다. 논문이 계산한 손익분기점은 GPT-4o-mini, GPT-6 Luna, Claude Opus 5.5 순으로 질문 372개, 545개, 596개다. LoCoMo가 이 대화에 던지는 질문은 152개뿐이다.

비용과 정답률을 함께 놓고 봐도 결과는 같다. 같은 비용 이하에서 가장 높은 정답률을 잇는 선을 그리면, 그 선 위에 놓이는 것은 GPT-6 Luna의 BM25와 대화 전체, Claude Opus 5.5의 Pi다. Zep은 만드는 비용이 Mem0보다 낮았지만(부록 표 2 기준 GPT-4o-mini 0.092달러, GPT-6 Luna 0.103달러, Claude Opus 5.5 6.224달러) 정답률은 네 가지 기억 방식 가운데 모든 모델에서 가장 낮았다. Mem0와 Zep은 어느 모델에서도 이 선에 오르지 못했다. 연구자는 더 강한 모델에게는 필요 없는 기억을 만드느라 치르는 이 값을 '기억 세금'이라고 불렀다.

## 5. 둘째 발견, 기억의 품질은 그것을 만든 모델이 정한다

Mem0와 Zep에서는 기억을 만드는 모델과 읽는 모델이 같다. 다만 저장해 둔 조각을 꺼내 오는 검색 단계에는 언어 모델이 끼지 않는다. 그래서 읽는 모델만 바꿔 끼울 수 있다. 연구자는 각 모델이 만든 기억을 다른 모델에게 읽혀 봤다.

표 3은 논문 부록 표 3을 옮긴 것이다. 결과는 한 방향을 가리킨다. 읽는 모델이 강해져도, 만든 모델이 빠뜨린 것은 되살리지 못한다.

Zep에서 이 현상이 뚜렷하다. GPT-4o-mini가 만든 그래프를 세 모델이 읽었을 때 정답률은 43%, 43%, 45%였다. 가장 강한 Claude Opus 5.5가 읽어도 2%p밖에 오르지 않았다. 같은 Claude Opus 5.5가 직접 만든 그래프를 읽었을 때는 87%였다. Mem0도 순서는 같았지만 격차가 작았다. GPT-4o-mini의 저장소에서는 78%, 83%, 84%, Claude Opus 5.5의 저장소에서는 89%, 91%, 95%였다.

AlphaSignal은 이를 상담 사례로 풀었다. 불만 접수 내용을 요약하면서 구매 날짜를 빠뜨리면, 나중에 보증 기간을 묻는 질문에는 아무리 똑똑한 모델도 답할 수 없다. 요약에서 빠진 정보는 요약만 봐서는 복원할 길이 없다.

연구자는 이를 두고 에이전트 메모리에는 '천장'이 있다고 표현했다. 미리 정리하는 방식에서는 정리하는 순간의 판단이 이후 모든 답의 상한선이 된다.

## 6. 셋째 발견, Pi의 99%와 그 안의 단서 두 가지

Claude Opus 5.5와 Pi의 조합이 비용 대비 정답률에서 가장 앞섰다. 한 바퀴에 6.95달러를 쓰고 정답률 99%를 기록했다. 같은 모델로 대화 전체를 넣으면 95%에 17.84달러였다. Pi는 질문 하나에 입력 토큰을 약 1만 개 읽었고, 그중 7,900개는 캐시된 입력이었다. 대화 전체 방식은 질문마다 2만 8,900개를 읽었다. 전체를 다시 읽는 대신 필요한 부분만 찾아 읽은 결과다.

같은 모델이라도 에이전트에 따라 비용 차이가 컸다. Codex는 98%에 25.41달러, Claude Code는 97%에 28.41달러였다. 논문은 같은 모델이 하니스(harness, 모델을 감싸 도구와 실행 흐름을 정하는 틀)에 따라 비용이 크게 다른 이유로 Arena의 HarnessTax 연구를 인용했다. 이 지면은 그 연구를 직접 읽지 않았다.

첫째 단서는 Pi가 틀린 한 문제다. 질문은 2023년 10월 13일에 Caroline이 Melanie에게 어떤 그림을 보여 줬느냐고 묻는다. 정답지는 파란 줄무늬가 있는 추상화라고 적었다. 그런데 대화를 보면 그 그림을 보여 준 사람은 Melanie이고, Caroline은 소묘를 보여 줬다. Pi는 이를 정확히 짚고도 오답 처리됐다. Claude Opus 5.5를 쓴 대화 전체, Codex, Claude Code도 같은 오류를 지적했다가 똑같이 오답이 됐다. 이 한 문제를 빼면 Pi는 나머지 151문제를 모두 맞혔다.

둘째 단서는 사진 설명이다. Claude Opus 5.5 기준으로 Pi는 대화 전체 방식이 틀린 일곱 문제를 맞혔고, 대화 전체가 맞힌 문제는 하나도 틀리지 않았다. 그런데 일곱 문제 가운데 여섯은 답의 근거가 사진이 붙은 턴에 있었다. Pi는 사진 설명을 읽을 수 있었고 대화 전체 방식은 읽을 수 없었다. Codex가 대화 전체보다 더 맞힌 여섯 문제, Claude Code가 더 맞힌 네 문제도 모두 사진이 붙은 턴에 근거가 있었다.

## 7. 연구자가 직접 밝힌 한계

연구자는 이 연구가 작다는 점을 초록에서부터 밝혔다. 논문 6장에 적은 한계는 다섯 가지다.

첫째, 규모다. LoCoMo 대화 10개 가운데 하나만 썼고, 조합마다 한 번씩만 돌렸다. 몇 문제 차이는 다시 돌리면 뒤집힐 수 있다. 질문 152개에서 한 문제는 약 0.7%p다. Claude Opus 5.5에서 Pi(99%)와 Codex(98%), Claude Code(97%)의 차이는 몇 문제 수준이다. 한 숟가락 맛으로 냄비 전체의 간을 판단하는 셈이다.

둘째, 채점이다. 채점은 너그러운 기준을 적용한 GPT-4o-mini가 맡았고, 정답지에는 적어도 한 군데 오류가 있었다.

셋째, 사진 설명이다. 에이전트만 사진 설명을 읽을 수 있었다. 이 차이는 에이전트와 기억 방식 사이의 비교에 영향을 주고, 기억 방식끼리의 비교에는 영향을 주지 않는다.

넷째, 대화 길이다. 이 대화는 모든 모델의 컨텍스트 창에 다 들어갔다. 그래서 대화 전체를 넣는 방식이 늘 가능했다. 컨텍스트 창을 넘는 긴 기록이나 LongMemEval 같은 다른 벤치마크에서는 결과가 다를 수 있다.

다섯째, 설정과 가격이다. Mem0와 Zep은 기본 추출·검색 설정으로 돌렸고, 다른 설정에서는 더 잘할 수도 있다. 비용은 정가 기준이라 업체마다 다른 캐시 정책에 따라 달라진다.

이 지면이 덧붙일 단서도 있다. 부록 B에 따르면 에이전트 시도가 실패하거나 답 없이 끝나면 다시 돌리고, 받아들여진 시도만 셌다. 재시도가 몇 번 있었는지, 그 비용이 표 2에 들어갔는지는 논문에 적혀 있지 않다. 또 연구자는 대화 전체 방식에도 사진 설명을 줬다면 격차가 얼마나 줄었을지를 직접 재지는 않았다.

## 비유로 이해하기

오랜 단골손님을 맡은 동네 서점 주인을 떠올려 보자. 손님과 몇 달 동안 주고받은 편지가 상자에 가득하다. 손님이 "지난번에 추천해 준 책 제목이 뭐였죠?" 하고 물으면, 주인은 어떻게 답해야 할까.

Mem0와 Zep은 편지가 올 때마다 색인 카드에 요점을 적어 두는 방식이다. 카드 상자만 보면 되니 답이 빠르다. 하지만 카드를 쓰는 데 시간과 품이 든다. 그리고 카드에 안 적은 내용은 나중에 아무리 꼼꼼한 사람이 와도 찾을 수 없다. 견습생이 카드를 대충 썼다면, 경력 많은 주인이 그 카드를 읽어도 답은 거기서 거기다. 3장과 5장의 결과가 이것이다.

대화 전체 방식은 질문이 올 때마다 편지 상자를 처음부터 끝까지 다시 읽는 방식이다. 빠뜨리는 것은 없지만 매번 같은 편지를 다시 읽느라 시간이 든다.

Pi 같은 에이전트는 편지 상자를 그대로 두고, 질문을 듣고 나서 돋보기를 들고 관련 있어 보이는 편지만 골라 읽는 방식이다. 노련한 주인이라면 이 방식이 빠르면서도 정확하다. 서툰 견습생에게 돋보기를 쥐여 주면 상자를 열어 보지도 않고 짐작으로 답하기도 한다. GPT-4o-mini와 짝지은 Codex와 Claude Code의 낮은 점수가 그런 모습이다.

색인 카드가 쓸모없다는 뜻은 아니다. 같은 손님이 똑같은 종류의 질문을 수백 번 던진다면 카드를 만들어 두는 편이 결국 싸다. 이번 실험에서는 질문이 152개뿐이라 카드값을 뽑지 못했을 뿐이다.

## 내가 보는 의미

이 논문은 새 기억 장치를 내놓은 연구가 아니다. 이미 쓰이는 방식들을 같은 조건에 세워 놓고 정답률과 영수증을 함께 들여다본 측정 연구다. 그 점에서 쓸모가 있다. 에이전트 메모리를 다루는 많은 평가가 정답률만 비교하는데, 이 연구는 기억을 만드는 비용까지 한 장부에 올렸다.

가장 무게가 실리는 발견은 '기억의 천장'이라고 본다. 비용과 정답률 순위는 모델이 바뀌면 다시 뒤집힐 수 있다. 하지만 정리하는 순간 빠진 정보는 되돌릴 수 없다는 점은 구조적인 문제다. 미리 정리하는 기억을 쓰더라도 원본 기록을 함께 남겨 두라는 실무 교훈이 여기서 나온다. AlphaSignal도 같은 결론을 실무 지침으로 정리했다.

반대로 "기억 장치는 필요 없다"고 읽는 것은 경계해야 한다. 이 대화는 모든 모델의 컨텍스트 창에 다 들어가는 길이였다. 실제 상담 기록처럼 몇 달, 몇 년 치가 쌓이면 대화 전체 방식은 아예 쓸 수 없고, 에이전트 검색의 비용도 달라진다. 조합마다 한 번씩만 돌린 실험에서 1~4%p 차이는 우연과 구분하기 어렵다. 에이전트의 우위 가운데 상당 부분은 사진 설명이라는 정보량 차이에서 왔다.

연구자가 그리는 다음 단계도 눈여겨볼 만하다. 논문 6장은 기억 시스템이나 하니스를 자동으로 탐색해 찾는 연구도 있지만, 그렇게 찾은 것 역시 질문이 오기 전에 고정된다고 지적한다. 대신 강한 모델에게는 원본 기록을 정확히, 뜻으로, 벡터로 검색하는 도구를 쥐여 주고 모델이 직접 쓰게 하자는 쪽에 무게를 둔다. 연구자는 앞으로의 진보가 또 하나의 기억 시스템보다는 grep 다음에 나온 ripgrep 같은 모습일 수 있다고 적었다. 더 좋은 검색 도구가 곧 더 좋은 기억이 된다는 뜻이다.

이 전망에는 이 지면도 절반만 동의한다. 검색 도구를 잘 쓰는 것은 이번 실험의 Claude Opus 5.5 같은 강한 모델의 이야기다. GPT-4o-mini와 짝지은 Codex는 네 질문 중 한 질문에서 파일을 열지도 않았다. 비용을 아끼려고 작은 모델을 쓰는 현장에서는 미리 정리한 기억이 여전히 쓸모 있는 땜질일 수 있다.

앞으로 지켜볼 것은 다섯 가지다.

1. **대화 10개 전체로 넓힌 재실험.** 연구자는 conv-26의 방법별 정답률이 전체 대화 10개와 비슷한 흐름이라고 적었지만, 그 근거 수치는 논문에 없다. 나머지 대화와 반복 실행에서도 순위가 유지되는지가 첫 확인 지점이다.
2. **컨텍스트 창을 넘는 기록.** 대화 전체 방식을 쓸 수 없는 길이에서 에이전트 검색과 미리 정리한 기억이 어떻게 갈리는지가 실무에 더 가까운 질문이다.
3. **입력 조건을 맞춘 비교.** 모든 방법에 사진 설명을 똑같이 주면 에이전트와 대화 전체 사이의 정답률 차이가 얼마나 남는지 봐야 한다.
4. **손익분기점의 현실성.** 같은 기록에 질문이 수백 번 쌓이는 업무, 예컨대 고객 관리 에이전트에서 질문 372~596개라는 Mem0의 손익분기점을 실제로 넘는지가 기억 세금을 낼 만한지를 가른다.
5. **공개 코드의 재현.** 코드와 데이터가 MIT 라이선스로 공개됐다. 다른 연구자가 다른 대화와 설정으로 같은 결론을 얻는지가 다음 확인 지점이다.

- 기억을 만든 모델과 읽은 모델의 교차 결과를 부록 표 3에서, 사진 근거 여부별 정답률을 부록 표 4에서 옮겼다.
- Pi의 6.95달러와 99%, 질문당 입력 토큰 약 1만 개(캐시 7,900개) 대 2만 8,900개, Codex 25.41달러·98%, Claude Code 28.41달러·97%, 정답지 오류 사례, 일곱 문제 중 여섯이 사진 근거라는 점을 PDF 5장에서 확인했다.
- 코드 저장소 `https://github.com/zedong-peng/memorytax`가 인터랙티브 페이지에 연결돼 있고, GitHub API로 MIT 라이선스 공개 저장소임을 확인했다.

### 낮은 확신도
- 인터랙티브 페이지에는 날짜가 2026년 10월 11일로 적혀 있다. arXiv 제출일(10월 21일)과 다르며, 이 지면은 arXiv 제출 이력을 기준으로 썼다.
- conv-26의 방법별 정답률이 대화 10개 전체와 비슷하다는 설명은 논문 본문의 서술이고, 근거 수치는 논문에 없다.
- 실패한 에이전트 시도를 다시 돌린 횟수와 그 비용 반영 여부는 논문에 적혀 있지 않다.
- 그림 1~4의 곡선은 이 지면이 숫자로 옮기지 않았다. 비용과 정답률의 경계선 위에 놓인 조합은 본문 서술을 따랐다.
- 상담 에이전트의 구매 날짜 예시는 AlphaSignal의 설명이고, 논문에는 없다.

### 채택하지 않음
- "에이전트 메모리는 이제 필요 없다"는 해석. 같은 기록에 질문이 많이 쌓이면 Mem0가 본전을 뽑을 수 있고, 연구자도 미리 설계한 기억이 비용 절충안으로 남을 수 있다고 적었다.
- "원본 검색이 대화 전체보다 정확하다"는 해석. 사진과 무관한 질문 88개에서는 한 문제 차이였고, 연구자도 이 연구로 가릴 수 없다고 밝혔다.
- "Pi가 Codex와 Claude Code보다 낫다"는 일반화. 정답률 차이는 몇 문제 수준이고, 조합마다 한 번만 돌렸다.
- 뉴스레터 요약 문구. 출발점으로만 썼고, 수치는 모두 arXiv 원문에서 옮겼다.
